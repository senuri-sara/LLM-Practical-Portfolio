# Summary – Working with an LLM as a Development Partner

This activity was completed individually, with an LLM (Claude) acting as the discussion partner throughout the design process. This summary describes how the LLM was used and what was learned.

## How the LLM Was Used
| Stage | Focus of the prompt | Outcome |
|---|---|---|
| Problem analysis | Root causes, why existing solutions fail and how common the problem is | External and internal causes identified, supported by research |
| Target user | A realistic persona based only on real details | Persona "Tharushi", corrected after the first version included invented details |
| Idea generation | Six ideas mixing apps, devices and hybrid products, each with a weakness | Six concepts compared in a table |
| Evaluation | Strengths, weaknesses, name options and features of the chosen idea | StudyNest Hub refined with original features and renamed StillHour |
| Prototype | Four app screens and one device shown together | StillHour visual prototype |

## Prompt-Engineering Techniques Used
- **Role prompting:** asking the LLM to act as a researcher, UX designer or startup advisor produced more expert and focused answers.
- **Clear context:** describing real habits and the solutions already tried led to personal rather than generic responses.
- **Structured tasks and format:** numbered tasks and requests for tables, headings and key insights made the answers easier to compare and use.
- **Constraints:** instructions such as "do not add any details that I have not mentioned" reduced invented information.

## Key Decisions Made Without the LLM
- Selecting StudyNest Hub because it addressed both external and internal distractions
- Adding the visual countdown, the combined lamp and noise device, and bedtime light mode
- Renaming the product from the suggested "FocusNest" to StillHour

## Reflection
The LLM was highly effective for analysing the problem, organising information and generating ideas quickly. However, it sometimes filled gaps with invented details, and its suggestions needed to be checked against real experience and original sources. The strongest results came from combining the speed of the LLM with human judgement and personal experience.
